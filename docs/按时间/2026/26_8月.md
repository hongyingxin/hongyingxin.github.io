# 2026年8月

## 8月26

记一次 Cursor MCP内容的返回

之前使用 MCP 的时候能够在对话窗口上下文查看，自从更新了 lanhu-node 版本后，就一直看不了。

今天才知道这是 Cursor 处理 MCP 工具返回内容的方式，共有两种，inline 和 spill。

- inline 是内联，MCP 返回的内容结果比较短，直接在窗口上下文中返回

- spill 是溢出落盘，当 MCP 返回的内容结果太长，超出 Cursor 自身的限制（目前未知长度是多少），则 Cursor Agent 不塞进对话，而是写成一个`.txt`文件，然后返回一个路径，工具结果会有一句：`Large output has been written to <path>`，即`agent-tools`临时文件

`agent-tools`临时文件生命周期是会话级别，命名方式为`UUID`，新对话通常找不到旧文件，过期时间未知。

当前使用版本为`Cursor 2.5`

## 8月7

新增本地新增了一个头饰的`pag`格式文件，本地测试没问题，但是提交部署到线上的时候播放404。

```text
Whitelabel Error Page
This application has no explicit mapping for /error, so you are seeing this as a fallback.

Fri Aug 07 17:00:21 CST 2026
There was an unexpected error (type=Not Found, status=404). 
```

这个报错信息说明 .pag 请求被 nginx 转给了 Spring 后端，没有走静态文件目录。本地 dist/static/pag/ 里虽然有文件，但线上 nginx 白名单里没有 .pag 这个扩展名。

这种情况下需要运维去修改`nginx`配置，将`.pag`文件加入到静态文件白名单中。

```nginx
location ~* \.(html|js|css|png|jpg|webp|pag|...)$ {
    # 静态文件
}
```

但是我问北美大豆包时，给我一个意想不到的答案，修改`pag`文件的后缀名，并且这种修改还可以正常播放视频。于是去了解这方面的知识。

1. 扩展名只是“标签”，`.pag`、`.webp`、`.bin` 都只是文件名后缀，不会改文件内容。

2. 播放流程看的是字节，不是后缀。libpag 解析的是 PAG 格式的二进制数据，不会检查“是不是 .pag 后缀”。
只要 arrayBuffer 里是合法的 PAG 数据，就能播。

```js
fetch(url)                    // 按 URL 拉文件
  → resp.arrayBuffer()        // 读成二进制
  → PAGView.init(arrayBuffer) // libpag 解析内容
```

3. 当然，也可以直接把后缀名去掉，但是去掉的话还是会被`nginx`转给后端，后端会返回404。
