## 9月14

### 从气泡变形到点九图：一次 H5 留言板的实战记录

这次做国庆活动 H5，留言板的气泡被提了一个问题：背景上的装饰变形了。

同一套气泡要出现在三个地方：选择气泡的格子、发送成功后的预览，以及祝福板的跑马灯。前两处需要固定宽度，跑马灯则需要跟着文字变长。原先用 `img` 配合 `object-fit: fill`，或者用 `background-size: 100% 100%` 撑满容器，文字一长，左右的花朵、翅膀和边框就一起被拉宽。

查资料时看到了 [《前端怎么实现点九图？看这里》](https://juejin.cn/post/7290940908623495227)，文章介绍了用 `border-image` 实现类似点九图的效果。结合这次调试记录，把素材、切分参数和布局之间的关系重新整理一下。

#### 1. 先确定图片的哪一部分可以拉伸

九宫格切分会把图片分成四个角、四条边和中间区域。对于这次高度固定、宽度变化的气泡，可以把上下切分设为 `0`，简化成左右三段：

```text
源图宽 134，高 100：

┌──────────────┬───────────┬──────────────┐
│ 左侧装饰 70  │ 中间 14   │ 右侧装饰 50  │
└──────────────┴───────────┴──────────────┘

宽度增加后：

┌──────────────┬─────────────────────────┬──────────────┐
│ 左侧装饰 70  │ 中间区域沿水平方向拉伸  │ 右侧装饰 50  │
└──────────────┴─────────────────────────┴──────────────┘
```

这里的“左右不变形”有前提：显示高度和左右装饰宽度要按源图的同一比例缩放，然后再增加中间区域的宽度。如果只把高度从 `100` 改成 `80`，左右宽度仍保持原值，装饰也会被压扁。

这次最终调好的参数是左 `70`、右 `50`。它对应的是当时的素材，换一张图就需要重新检查切分位置。

#### 2. slice 切源图，width 管显示尺寸

先看核心配置：

```css
.bubble--patch {
  box-sizing: border-box;
  height: 100px;
  border-style: solid;
  border-color: transparent;
  border-width: 0 50px 0 70px;
  border-image-source: url('./bubble.png');
  border-image-slice: 0 50 0 70 fill;
  border-image-width: 1;
  border-image-repeat: stretch;
}
```

`bubble.png` 是示例文件名，需要替换为切分位置匹配的气泡素材。四个 slice 值按**上、右、下、左**排列；对 PNG、WebP 这样的位图，无单位数字表示源图像素偏移。`fill` 用来保留中间区域，否则中间默认不绘制。[MDN：border-image-slice](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image-slice)

这几个属性可以放在一起理解：

| 配置 | 在这次实现中的作用 |
| --- | --- |
| `border-image-source` | 指定当前气泡的图片 |
| `border-image-slice: 0 50 0 70 fill` | 在源图上切出左 70、右 50，并绘制中间区域 |
| `border-width: 0 50px 0 70px` | 给左右装饰留出布局空间 |
| `border-image-width: 1` | 图片边框的绘制宽度取对应边框宽度的 1 倍 |
| `border-image-repeat: stretch` | 拉伸切出来的区域，填满对应绘制区域 |

原项目用了 `rem()` 做适配，`$root-value` 是 `75`。把尺寸转换成 rem 时，slice 仍然保留源图上的数字：

```scss
@use 'sass:math';

@function rem($value) {
  @return math.div($value, 75) * 1rem;
}

.bubble--patch {
  height: rem(100);
  border-width: 0 rem(50) 0 rem(70);
  border-image-slice: 0 50 0 70 fill;
}
```

这里的函数只负责单位转换，页面仍需沿用项目已有的根字号适配。`rem(50)` 决定屏幕上画多宽，slice 里的 `50` 决定从源图右侧取多少像素，两者不能一起做 rem 转换。

另外，`border-image-repeat` 支持 `stretch`、`repeat`、`round`、`space`，没有 `no-repeat`。参考文章中的 `border-image-repeat: no-repeat` 是无效声明；它看起来可能仍能工作，是因为在没有其他有效声明时会使用初始值 `stretch`。[MDN：border-image-repeat](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image-repeat)

#### 3. 我踩过的 border-width: 0，需要补充前提

最初的交接笔记里记了一句：“不要写 `border-width: 0`，必须用真实边框让左右帽占位。”对最终采用的写法，这个提醒是有用的，但不能当成所有点九实现的规则。

`border-image-width` 的默认值是 `1`，无单位数字表示对应 `border-width` 的倍数。因此，使用默认值时把边框宽度清零，左右图片边框的绘制宽度也会变成零。[MDN：border-image-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image-width)

```css
/* 这种组合会把图片边框的绘制宽度一起清零 */
border-width: 0;
border-image-width: 1;
```

不过，显式指定 `border-image-width` 的长度值，可以把绘制尺寸与真实边框宽度分开。例如，在已经设置好图片、slice 和高度的前提下：

```css
border-style: solid;
border-width: 0;
border-image-width: 0 50px 0 70px;
padding: 0 50px 0 70px;
```

这一写法用 padding 给内容留空间；绘制宽度本身不会替内容占位。项目最后保留真实左右边框、使用 `border-image-width: 1`，让绘制尺寸和占位尺寸保持一致，调起来更直观。

所以，遇到左右装饰消失或被挤压时，要同时看计算后的 `border-width`、`border-image-width` 和容器尺寸。单凭一条 `border-width: 0`，不足以解释所有变形现象。

#### 4. 测试图正常，换回真实图又花了

这次调试里最有帮助的一步，是临时把三个位置都换成同一张已知可用的测试图。

测试图显示正常，换回真实气泡又出现问题，这让我把排查重点转向了素材。几类图片看起来都叫“气泡”，实际结构却不同：

| 素材 | 原始尺寸 | 当时的情况 |
| --- | --- | --- |
| 粉玫瑰测试图 | 112 × 80 | 左 30、右 51 的切法能得到正常效果 |
| 带等级、翅膀的接口气泡 | 134 × 100 | 直接套测试图参数会切进装饰，后来调整为左 70、右 50 |
| 设计稿中的完整卡片图 | 268 × 80 | 已合成完整视觉内容，当时不适合直接用作横向点九源图 |

尺寸只能辅助判断。真正要看的是：左右切线有没有穿过花朵、文字、翅膀，中间留下的区域能不能连续拉伸。完整卡片图如果把装饰或文字做进中间区域，CSS 无法自动把它们单独保护起来。

还可以先做一个简单计算：

```text
112 宽的测试图：112 - 30 - 51 = 31，中间还有 31 像素
134 宽的实际图：134 - 70 - 50 = 14，中间还有 14 像素
把新参数套回测试图：112 - 70 - 50 = -8，左右切分已经重叠
```

左右 slice 之和大于或等于源图宽度时，中间区域为空，增加 `fill` 也不能补出一段有效的中心图像。[W3C：Image Slicing](https://www.w3.org/TR/css-backgrounds-3/#border-image-slice)

因此，测试图和实际图不能只换 URL、不管参数。换图对比能缩小排查范围，但它只能证明“这张图配这组参数”可用。最终的 `70 / 50` 也不能作为所有气泡的通用配置。

#### 5. 三处共用皮肤，布局分别处理

气泡背景修好之后，还有一个容易混在一起的问题：文字应该怎样决定气泡尺寸。

| 场景 | 宽度规则 | 内容布局 |
| --- | --- | --- |
| 选择气泡 | 固定宽 268，皮肤区域高 100 | 文案相对整个气泡居中，允许换行 |
| 发送成功预览 | 固定宽 268 | 复用固定宽预览布局 |
| 祝福板跑马灯 | 随头像和文字撑开 | 内容保留在普通流中，单行显示 |

表里的数字沿用项目的设计尺寸，实际样式使用 `rem()`。这次最终把三处气泡文字统一成了 18、白色；这些是页面需求，点九本身不负责字体或文字对齐。

下面用简化后的 Vue 模板说明两种布局。示例沿用上面的 `.bubble--patch` 和 `rem()`，图片通过原项目类似的函数传入：

```js
function bubblePatchStyle(url) {
  return {
    borderImageSource: url ? `url(${JSON.stringify(url)})` : 'none',
  }
}
```

**固定宽预览：用外层作为居中参照。**

左边框是 70，右边框是 50，内容区域的中心与整个气泡的中心并不重合。绝对定位通常以定位祖先的 padding box 为包含块，按这个规则推算，直接在带非对称边框的元素里使用 `left: 50%`，仍会相对整个气泡偏移。[MDN：包含块](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Display/Containing_block)

整理成可复用示例时，可以增加一个无边框的外层，把皮肤与文案分别放进去：

```vue
<div class="bubble-preview">
  <div
    class="bubble--patch bubble-preview__skin"
    :style="bubblePatchStyle(bubbleUrl)"
    aria-hidden="true"
  ></div>
  <span class="bubble-preview__text">祝福的话写在这里</span>
</div>
```

```scss
.bubble-preview {
  position: relative;
  width: rem(268);
  height: rem(100);
}

.bubble-preview__skin {
  position: absolute;
  inset: 0;
}

.bubble-preview__text {
  position: absolute;
  inset: 0;
  display: flex;
  align-items: center;
  justify-content: center;
  box-sizing: border-box;
  padding: 0 rem(70);
  font-size: rem(18);
  line-height: 1.4;
  color: #fff;
  text-align: center;
  overflow-wrap: anywhere;
}
```

文案层相对外层居中，不受皮肤左右边框不对称的影响。这里用对称的 70 留出装饰安全区；实际留白仍要看素材，固定高度的预览也需要约束文案行数，不能容纳任意长文本。

**跑马灯：让头像和文字参与宽度计算。**

```vue
<div
  class="bubble--patch bubble-marquee"
  :style="bubblePatchStyle(bubbleUrl)"
>
  <img class="bubble-marquee__avatar" :src="avatarUrl" alt="" />
  <span class="bubble-marquee__text">这是一条长度不固定的祝福</span>
</div>
```

```scss
.bubble-marquee {
  display: inline-flex;
  align-items: center;
  width: fit-content;
  flex-shrink: 0;
  gap: rem(5);
}

.bubble-marquee__avatar {
  width: rem(30);
  height: rem(30);
  flex-shrink: 0;
  border-radius: 50%;
}

.bubble-marquee__text {
  font-size: rem(18);
  line-height: 1.4;
  color: #fff;
  white-space: nowrap;
}
```

跑马灯复用的是气泡皮肤，宽度由头像、间距、文字和左右边框共同撑开。这里没有给文字设置绝对定位；如果沿用预览里的绝对定位，文字会脱离普通流，容器就无法靠它计算内容宽度。[MDN：position](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position)

`white-space: nowrap` 保留单行效果。很长的留言可能比视口宽，这是跑马灯需要处理的情况，外层轨道负责裁切和移动，具体动画不在这个示例里展开。

#### 6. 总结

一开始我认为气泡有设计规范，左右占比是固定的，后面经过沟通发现并没有。所以思路就是保证两边装饰的宽度不变，然后让中间区域可以拉伸。
